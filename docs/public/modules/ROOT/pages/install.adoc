= Install
:description: Install the Amiterra CLI on Linux or macOS, verify the checksum, or build from source.
:keywords: install, CLI, binary, checksum, verify

== Prebuilt binaries

[source,bash]
----
curl -fsSL https://get.amiterra.io | bash
----

The installer detects `linux/x86_64`, `linux/aarch64`, and `darwin/aarch64`,
verifies the download against the published SHA-256 checksums, and installs two
executables: `amiterra` and the `ami` alias.

Install location:

* root: `/usr/local/bin`
* non-root: `~/.amiterra/bin`, plus symlinks into the first writable directory
  already on your `PATH` (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`,
  `~/bin`, `~/.cargo/bin`)
* override with `AMITERRA_INSTALL_DIR=<dir>`

With no arguments, the installer continues straight into the guided
`ami init` wizard (reconnecting the terminal if the script was piped). To
install only, pass a command instead:

[source,bash]
----
curl -fsSL https://get.amiterra.io | bash -s -- --version
ami --version && ami doctor
----

System changes happen only when you run `ami init` — the install step itself
only writes the binaries.

=== Verify manually

Release files live under `https://get.amiterra.io/dist/latest/`
(`amiterra-linux-x86_64`, `amiterra-linux-aarch64`, `amiterra-darwin-aarch64`,
plus `SHA256SUMS`):

[source,bash]
----
curl -fsSL https://get.amiterra.io/dist/latest/SHA256SUMS -o SHA256SUMS
curl -fsSL https://get.amiterra.io/dist/latest/amiterra-linux-x86_64 -o amiterra
shasum -a 256 -c SHA256SUMS --ignore-missing
sudo install -m 0755 amiterra /usr/local/bin/amiterra
sudo ln -sf /usr/local/bin/amiterra /usr/local/bin/ami
----

== From source

[source,bash]
----
git clone https://github.com/amiterra/amiterra-cli.git
cd amiterra-cli
make build
sudo install -m 0755 target/release/amiterra /usr/local/bin/ami
----

Build requirements: Rust 1.85+ (edition 2024). `make test` runs the unit suite;
`make test-cluster` runs the full multi-node lifecycle test in local QEMU VMs.

== Air-gapped install

Copy the statically linked binary to the target host — there is no runtime
dependency to fetch:

[source,bash]
----
scp amiterra-linux-x86_64 root@node:/usr/local/bin/amiterra
ssh root@node 'ln -sf /usr/local/bin/amiterra /usr/local/bin/ami && ami --version && ami doctor'
----

The GitOps layer (Flux controllers) is *vendored into the binary* with a pinned
checksum, so `ami gitops bootstrap` also works without internet access.
