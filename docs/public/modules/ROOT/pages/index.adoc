clouds and bare-metal nodes: Day-0 bootstrap, guarded kernel tuning, cluster
lifecycle, GitOps, and diagnostics — in one static binary.

== The 60-second tour

[source,bash]
----
# Install (verifies SHA-256 checksums) — then continue into the guided setup
curl -fsSL https://get.amiterra.io | bash

# See what you got
sudo ami status
----

The setup wizard is interactive and conservative: base Kubernetes comes up, but
optional layers (performance tuning, GitOps) are applied only when you say so.
Prefer to install without starting the wizard: `curl -fsSL https://get.amiterra.io | bash -s -- --version`.

== Why you can trust it

* **Opt-in everything.** Nothing beyond the minimal base is applied without an
  explicit choice — a prompt, a flag, or an explicit command.
* **Reversible — and verified.** Tuning captures a baseline before touching
  anything; `ami tune rollback` restores it. `ami uninstall` reverts the host
  and *re-probes it* before claiming restoration — leftovers are listed, never
  silently ignored.
* **No secret exfiltration.** Join tokens are never printed in install output;
  deploy keys are generated on the node and the private key never leaves it.
  No telemetry is sent without consent.
* **Guardrails, not guesswork.** Dangerous kernel parameters are refused by
  policy (`kernel.core_pattern`, `ip_forward` in profiles, panic policy).
* **Predictable.** Stable exit codes, `--json` on reporting commands,
  idempotent converge — re-running a command is safe.
* **No lock-in.** Your Git repository is the source of truth; FSL-1.1-ALv2
  converts to Apache-2.0 after two years. Air-gapped operation works.

Details and the full model: xref:safety.adoc[Safety & Reversibility].

== What one binary covers

[cols="1,2"]
|===
|Area |Commands

|Cluster lifecycle
|`ami init`, `ami join`, `ami join-command`, `ami up`, `ami down`, `ami status`

|Host tuning (opt-in, reversible)
|`ami tune plan`, `ami tune apply`, `ami tune rollback`, `ami tune status`

|GitOps (Flux + Git binding, opt-in)
|`ami gitops bootstrap`, `ami gitops status`

|Storage tiers
|`ami storage status`, `ami storage plan`, `ami storage prepare`, `ami storage rollback`

|Diagnostics
|`ami doctor` (alias: `ami preflight`)

|Removal
|`ami uninstall`
|===

Full details: xref:commands.adoc[Command Reference].
